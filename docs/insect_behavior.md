# 拟真行为包

产品定位为仿昆虫运动方式的低成本四足机器蜘蛛。本文的动作全部基于昆虫真实行为，且**零硬件成本**——由已有 8 舵机与 Blender 关键帧管线实现。

## 1. 拟真原则

| 原则 | 说明 |
|---|---|
| 不装不具备的能力 | 多数昆虫翻不了身，机器人亦不自复位。叩头虫的弹跳翻身机制刻意不装 |
| 行为优先于功能 | 默认行为模仿昆虫（谨慎行走、快慢节奏、装死），非拟真行为需显式请求 |
| 借机制而非堆功率 | 昆虫跳远靠闩锁-弹簧储能（LA-MSA），非强肌肉；同类机制留作二期实验 |
| 观感即功能 | 表情动作承担交互功能（威慑、安抚、状态表达） |

## 2. 行为清单

| 名称 | 昆虫原型 | 行为描述 | 成本 |
|---|---|---|---|
| `play_dead` | 装死（thanatosis） | 收腿松弛，舵机 PWM 降档省电，纹丝不动 | 0 |
| `struggle` | 仰卧蹬腿 | 四腿朝天节律摆动，翻不了身只能挣扎 | 0 |
| `spawn` | 翻车姿态 | 仰卧静置，与 struggle 同姿态但静止 | 0 |
| `crouch_ready` | 蓄力蹲 | 蟑螂/蝗虫起跳前的压低姿态，威慑表达 | 0 |
| `alert` | 警戒 | 身体压低、腿外张、静止观察 | 0 |
| `wave` | 足部示意 | 单腿抬起摆动（拟螯虾/蜘蛛威吓） | 0 |
| `burst_walk` | 突发奔逃 | 快慢节奏的间歇行走（burst locomotion） | 0 |

## 3. 动作说明

### 3.1 `play_dead`（装死）

| 项目 | 内容 |
|---|---|
| 触发 | Web 按钮 / CLI `play play_dead` |
| 时长 | 默认 8s（可配置），随后恢复站立 |
| 动作 | 从当前姿态缓动到收腿位（四膝屈至 β=30°，髋回中立） |
| 舵机 | PWM 降至 30% 保持（省电 + 减少发热），恢复时升回 100% |
| 交互 | 期间忽略摇杆；急停仍然有效 |
| 中断 | 收到任何移动意图或 `estop_clear` 立即退出 |

**生物学依据**：多种甲虫、蜘蛛在受扰时蜷缩并停止运动，捕食者失去兴趣。这是昆虫最有效的防御之一，且实现成本仅是「放松」。

### 3.2 `struggle`（仰卧蹬腿）

| 项目 | 内容 |
|---|---|
| 触发 | 翻车后手动触发（Web 按钮 / CLI `play struggle`）；二期可由 IMU 自动检测 |
| 时长 | 循环播放（`loop=true`），直到收到新命令 |
| 动作 | 四腿朝天（膝屈至 β=25°、髋回中立），以 1.2Hz 频率交替蹬腿：左前右后与右前左后交替抬起 |
| 幅度 | 髋 ±20°，膝在 25°~45° 间往复 |
| 观感 | 无望但有生命感——恰是「翻不了身」的拟真表达 |

**生物学依据**：仰卧的甲虫、蜘蛛以节律性蹬腿挣扎，等待外力（墙角、枯枝）或人工帮助。这是本产品「不装自复位」原则的正向补偿：装不了复位，装挣扎。

### 3.3 `spawn`（翻车姿态）

| 项目 | 内容 |
|---|---|
| 触发 | Web 按钮 / CLI `pose spawn`；翻车后用于摆正观察 |
| 动作 | 抬到与 struggle 相同的仰卧姿态，但静止 |
| 用途 | 调试期检查腹部仰面支撑凸台（P10）是否平稳、不压线 |

### 3.4 `crouch_ready`（蓄力蹲）

| 项目 | 内容 |
|---|---|
| 触发 | 持续按住 Web 按钮 / CLI `play crouch_ready` |
| 动作 | 四膝缓屈至 β=28°，机身压低至约 90mm，静止 |
| 时长 | 保持至释放或收到其他命令 |
| 语义 | 「即将动作」的威慑信号，蟑螂/蝗虫起跳前的典型压低姿态 |
| 注意 | **不做弹跳**（一期不做跳跃，见 docs/gait_design.md §1.2）。此姿态仅为表达 |

**生物学依据**：蝗虫、蟑螂、跳蛛在起跳前压低身体蓄能，蓄力姿态本身就是威慑信号。压低还有实际防御价值（降低重心、藏进阴影）。

**与二期的关系**：二期「弹性肌腱」实验会让此姿态衔接到实际弹跳——蓄力（慢充能）→ 闩锁释放（LA-MSA 机制）。一期只留姿态接口。

### 3.5 `alert`（警戒）

| 项目 | 内容 |
|---|---|
| 触发 | Web 按钮；二期可由雷达检测自动触发 |
| 动作 | 机身压低 15%（四膝同步屈），四腿外张 10°（髋角调整），静止 3s |
| 语义 | 「我看到你了」，不逃不攻 |

**生物学依据**：多数昆虫在察觉捕食者时先压低静止（躲避视野），若威胁持续才逃或反击。

### 3.6 `wave`（足部示意）

| 项目 | 内容 |
|---|---|
| 触发 | Web 按钮 / CLI `play wave` |
| 动作 | 左前腿髋摆动 ±25°、膝在 β∈[35°,50°] 往复，周期 0.8s，循环 3 次；其余三腿保持站立 |
| 语义 | 友好的交互表情 |

**生物学依据**：蜘蛛以足部动作进行求偶、威吓、方向指示；螯虾以螯足示意。抬起单腿是最容易被人类读懂的「打招呼」。

### 3.7 `burst_walk`（突发奔逃）

| 项目 | 内容 |
|---|---|
| 触发 | Web 按钮；二期可由视觉触发 |
| 动作 | Trot 步态，速度在 20%~90% 间按 0.4s 快 / 1.2s 慢交替，周期 1.8s |
| 总时长 | 约 3s，4 个 burst |
| 语义 | 逃跑时的爆发式节奏 |

**生物学依据**：昆虫运动普遍为 burst-locomotion（突发-间歇），如蟋蟀、蚂蚁的快速奔跑与静止交替。此节奏本身是昆虫运动风格的显著特征，也便于用户在 Web 页上一眼分辨「这是虫子」而非「这是玩具」。

## 4. 实现方式

全部为关键帧序列，经 `posture` 组件的统一插值引擎播放。

| 动作 | 来源 | 复杂度 |
|---|---|---|
| `play_dead` / `alert` / `crouch_ready` | 内置于 `posture`（姿态插值即可，无需逐帧） | 低 |
| `struggle` / `wave` / `burst_walk` | Blender 导出 JSON → `kf_convert.py` → C 头文件；或 Web 上传 | 中 |

### 关键帧序列格式

见 docs/protocol.md §4。`struggle` 与 `wave` 需 `loop=true`，其余为一次性序列。

### Blender 骨架一致性

`tools/blender/build_rig.py` 生成的骨架必须与 docs/hardware.md §1 的关节轴向一致：

- 髋：竖直轴（Z），摆动方向为水平面前后
- 膝：水平轴垂直于本腿竖直平面；外八 40° 时该轴相对机身偏转 40°

导出的关节角是**关节空间**数据，固件只做插值，不做 IK 转换。

## 5. 优先级与触发方式

一期无 IMU、无雷达，全部手动触发（Web 按钮 / CLI）。二期扩展：

| 传感器 | 可自动触发的行为 |
|---|---|
| IMU | 翻车 → `struggle`（同时触发 `spawn` 姿态） |
| 雷达 | 检测到障碍 → `alert`；逼近 → `crouch_ready` |
| 相机 | 检测到接近物体 → `alert`；检测到目标 → `wave` |

**原则不变**：传感器只决定「触发哪个行为」，不进入运动控制环（docs/architecture.md §10）。

## 6. 交互设计

Web 页「昆虫行为」按钮组布局：

```
┌─────────────────────────────────────┐
│  ⚠ 急停 (常驻)                       │  ← 红底，触达友好
├─────────────────────────────────────┤
│  姿态: [站立] [蹲坐] [休息] [翻车]    │
├─────────────────────────────────────┤
│  行为: [装死] [挣扎] [蓄力蹲]         │
│        [警戒] [招手] [突发奔逃]        │
├─────────────────────────────────────┤
│  微调: [↑][↓][←][→]   姿态: [横滚][俯仰] │
└─────────────────────────────────────┘
```

行为按钮带 300ms 长按确认（避免误触触发装死等动作），急停无确认。

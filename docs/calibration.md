# 装配与标定流程

本文供未参与设计者独立完成装配与标定。所有数值引用 docs/hardware.md。

## 0. 安全须知

| 事项 | 要求 |
|---|---|
| 舵机供电 | 独立 UBEC 10A-Car，**输出拨 6.0V 档**；**禁止**用 ESP32 开发板 5V 带舵机 |
| 主控供电 | DC-DC 5.0V → ESP32 **VIN**；**禁止**外部 3.3V 回灌开发板 3.3V 引脚 |
| PCA9685 | VCC=**3.3V**（接 ESP32 3.3V）、V+=**6.0V**（接 UBEC），**两者禁止互连**；6.0V 前须实测二者是否隔离 |
| 共地 | 舵机轨与主控轨必须共地 |
| 锂电 | 2S 平衡充；调试时旁边备灭火砂袋；不要无人看管充电 |
| 上电顺序 | 先接信号与逻辑，最后接舵机电源；断电反之 |
| 首次上电 | 机器人**架空**（脚不着地），且手中握急停/能立刻断电 |
| 螺丝 | M3 用螺纹胶固定轴承座类零件（受力件），电子件用铜柱不压螺丝 |

> ### 首次上电前：确认 UBEC 输出档位
>
> UBEC 10A-Car 输出为三档可选 **6.0V / 7.4V / 8.4V**。
> **必须逐字确认拨到 6.0V 档再通电。** MG996R 上限 6V，拨到 7.4V 或 8.4V，
> 8 只舵机会在数秒内烧毁，且没有任何保护能拦住。
>
> 校准开始前用万用表实测 PCA9685 电源轨电压确认一次：**6.0V ± 0.2V**。
> 舵机全部接上后再测一次（线损压降应 < 0.3V）；若此时已低于 5.5V，先查接线与
> 保险丝，不要继续标定。

> ### 三路电压逐路实测（通电前依次量）
>
> 本机有三条互相独立的供电轨，**逐路确认后再插舵机**：
>
> | 轨 | 正常值 | 来源 | 量测点 | 出错后果 |
> |---|---|---|---|---|
> | 舵机轨 | **6.0V ± 0.2V** | UBEC 10A-Car | PCA9685 的 V+ 端子 | 7.4/8.4V 会烧 8 只舵机 |
> | 输入轨 | **5.0V ± 0.2V** | DC-DC 降压模块 | DC-DC 输出端 / ESP32 VIN | 误设 6V 顶坏开发板 |
> | 逻辑轨 | **3.3V ± 0.05V** | 开发板板载稳压 | ESP32 的 3.3V 引脚 | 过低触发 brownout |
>
> **单腿台架测试例外**：用固定 5.0V 电源时，舵机轨与输入轨同为 5.0V，
> 量一条即可。5.0V 对 VCC（≤5.5V）与舵机（≤6V）都安全，与模块是否隔离无关。
>
> 另需确认：
>
> - **PCA9685 的 VCC 与 V+ 不可互连**（3.3V 与 6.0V，误插会损坏模块与主控）
> - **不要同时接 VIN 5V 与 USB**。两个 5V 源并联，除非开发板有输入并联保护，
>   否则应断开其中一路。调试期建议：USB 供电时不接 VIN，接 VIN 时拔掉 USB
> - PCA9685 的 **OE 接到 GPIO25**，10kΩ 上拉至 3.3V。**上电瞬间输出为关断态**，
>   固件初始化完成后才会使能——这是刻意的安全设计，不是故障

> ### 装机前必做：实测 PCA9685 的 V+ 与 VCC 是否隔离
>
> **这一步在接线前做，且必须断电。**
>
> 舵机轨能不能用 6.0V，取决于手上这块模块的 V+ 是否与芯片 VCC 隔离：
>
> | 测得 | 判定 | 处理 |
> |---|---|---|
> | 开路（∞ 或 >1kΩ） | 已隔离 | 可用 6.0V 舵机轨 |
> | 接近 0Ω，或有 diode drop | **已短接** | **禁止接 6V**，舵机轨降到 5.0V |
>
> 短接的模块上，6V 会经PCB 直接灌进芯片 VDD——那是真正的芯片超压，
> 并会连带把 6V 送到 ESP32 的 3.3V 轨。廉价克隆板常有此问题，
> 原版 Adafruit 模块则是隔离的。
>
> 量完把结果填回 docs/hardware.md §4 的「实测记录」表，换板时不必重判。

## 0.5 单腿台架测试

整机装配前，用 1~2 只舵机和已打印的膝关节件确认机械行程与起止角。
**本节流程与 §1~§8 独立**，测完即可继续整机装配。

### 0.5.1 供电：USB 供主控，电源只供舵机轨

台架用固定 **5.0V** 开关电源（3A 或更大）。**不要**用它给 ESP32 的 VIN 供电——
那会让 5V 与 USB 的 5V 两个源并联。ESP32 只由 USB 供电：

```
USB ─────────────► ESP32（板载稳压产 3.3V）
                    ├── 3.3V ──► PCA9685 VCC
                    └── GND ─┐
USB GND ──────────────────┤ 共地
                         │
5.0V 电源 ───────────────┼──► PCA9685 V+（舵机轨）
        GND ────────────┘
```

5.0V 同时满足 VCC（≤5.5V）与舵机（≤6V），**与模块是否隔离无关**，
所以这一阶段不需要做 §0 的隔离性实测。

**OE 的 10kΩ 上拉仍然必须接**——台架要反复插拔改线，上电瞬间输出状态
不确定的风险比整机更高。

```
GPIO25 ──► PCA9685 OE
 10kΩ
   │
  3.3V
```

### 0.5.2 烧录 bench 固件

台架模式关闭时，**上电瞬间舵机就会动**：`servo_init()` 把膝设成巡航
beta（出厂标定下约 1413µs），而 `motion_task()` 启动后每 2ms 调
`servo_tick()` 写 PWM。那个位置是用出厂默认脉宽算的，与实际机械零位无关。

bench 模式让 `servo_tick()` 不写任何 PWM，`cal enter` 也不再把 8 路拉中位，
因此上电全程静默。

```bash
./build.sh bench on      # 开启台架模式（自动清 build/ 与 sdkconfig）
./build.sh flash monitor
```

> **切换 bench 必须清 `build/` 与 `sdkconfig`**：IDF 只在首次生成时应用
> `sdkconfig.defaults`，而 `build/` 的 CMake 缓存里存着派生值——不清就会
> 编译出旧行为，然后烧进去一台「以为开了其实没开」的机器人。
> `build.sh bench` 已经代劳，不要手动改 Kconfig。

> `bench` 固件里机器人**完全不会动**，那是刻意的。调试完记得
> `./build.sh bench off` 恢复，否则整机装了也不会走。

### 0.5.5 确定膝关节机械起止角

命令在**串口监视器**（`./build.sh monitor`）里执行，退出键 `Ctrl + ]`。

**先收窄标定区间**——不能省：

```
> cal enter
OK 已进入标定模式（台架模式：不归中，舵机保持静默）
> cal set 0 1150 1850 1500 0 0
> cal set 1 1150 1850 1500 0 0
> leg show
```

出厂默认的 1000~2000µs 对 MG996R 已是贴死区，`leg` 命令会拒绝超出已标定
区间的参数。这两步就是那层保护。

**用 ch1（FL 膝）**。三档速度，按需要选：

| 目的 | 命令 | 600µs 区间耗时 |
|---|---|---|
| 先看行程全貌 | `leg sweep 1 1200 1800 fast` | 约 2s |
| 日常找起止点 | `leg sweep 1 1200 1800` | 约 4s（默认档 = normal） |
| 细看机构反应 | `leg sweep 1 1200 1800 slow` | 约 10s |

预设 = （step, dwell）绑定：fast 20/30、normal 15/50、slow 10/80。
也可直接给数字 `leg sweep 1 1200 1800 15 50`。

**上表的耗时是 600µs 区间的值**，它是参考区间而非固定属性——其他区间按
下式换算（`span` = `to_us - from_us`）：

```
跳数 steps   = ceil(span / step)
总时长        = steps × 2 × dwell      ← ×2 因为是「去一趟 + 回一趟」
```

| 区间 | fast | normal | slow |
|---|---|---|---|
| 300µs | 0.9s | 2.1s | 4.9s |
| 600µs | 1.9s | 4.1s | 9.8s |
| 1000µs（满量程） | 3.1s | 6.8s | 16.2s |

> ### ⚠️ 逼近机械极限用 `leg step`，不要用 `leg sweep`
>
> `sweep` 是连续推进，撞上极限后每一个越界的 step 都会变成一段持续堵转，
> 且逐跳累积。而 `slow` 档步长 10µs ≈ 膝关节 0.63°/步，**接近肉眼可辨下限**——
> 步长小于静摩擦或齿轮齿隙时可能出现「命令在动、输出轴没动」，你会误判成
> 「还没到极限」。
>
> `leg step` 每敲一次只动 5µs（可给 1），停住等你观察，说停就停：
>
> ```
> > leg step 1 +1
> ch1 = 1505us
> > leg step 1 +1
> ch1 = 1510us
> ```
>
> 看到抖动、阻力或异响，立刻 `leg release`。**阻转时间由你控制，而不是
> 由固定 dwell 累积。**

`leg sweep` 有 **60 秒上限**：预计耗时超出就拒绝执行并建议改用 `fast` 或
`leg step`，避免一个参数敲错就让串口长时间无响应（扫描期间 CLI 忙等
stdin，`estop` 也发不进去）。

该上限是**安全网而非功能约束**：合法区间最宽 1000µs，最慢的 `slow` 也只要
16s；触发 60s 需要的区间分别是 fast 20000µs / normal 7500µs / slow 3750µs，
均远超合法输入。

扫描会精确落在 `to_us` 上——区间长度不被 step 整除时，末跳是不足一个
step 的余数（例：1200→1800 step=250，得 1200/1450/1700/1800）。

**逼近极限一律用 `leg step`，不要用 `sweep`**：

```
> leg step 1 +1
ch1 = 1505us
> leg step 1 +1
ch1 = 1510us
```

> **为什么不能自动检测堵转**：固件没有电流采样（项目内无 ADC），
> 也没有舵机位置回读。「是否顶住」没有任何传感依据，只能靠人眼看。
> 所以 `sweep` 只用于看全貌；一旦接近极限，改用每敲一次只动 5µs 的
> `leg step`，停住等你观察。**看到抖动、阻力或异响，立刻 `leg release`。**

其他命令：

```
leg hold 1 1830     保持在指定脉宽，试机械阻力
leg release         8 路回中位（见到阻力时的第一反应）
```

### 0.5.6 记录与回填

把实测的起止脉宽填回标定：

```
> cal set 1 <min> <max> 1500 0 0
> cal save
> leg show
```

**`cal set` 不自动落盘**，只改 RAM；掉电后回到出厂默认 1000~2000µs
（对 MG996R 正是贴死区），所以最后那步 `cal save` 不能省。

`leg show` / `cal show` 会用 `*` 标出「本次开机后改过但尚未落盘」的通道：

```
ch  腿位.关节   min   max   neu   当前
0   FL.hip     1150  1850  1500  1200us
1   FL.knee    1200  1800  1500  1650us *
提示: 带 * 的通道改过但未落盘，掉电会丢失——执行 cal save
```

`*` 的语义是「本次开机后被改过」：开机时 RAM 即基线（从 NVS 读到，
或读不到时的出厂默认），都算干净；只有开机后的显式改动才置脏。
`cal save` 与 `cal load` 读写整组 blob，成功后一并清零。

四条改 RAM 标定的入口——CLI 的 `cal set` / `cal reset`，以及 Web 的 REST
与 WebSocket 两处——都经由 `servo_cal_set()`，因此 `*` 覆盖全部路径，
不会出现「串口改了但 Web 显示为已保存」的漏洞。

膝关节测得的 `[min, max]` 对应机械 β 范围，与设计值
`[21.3°, 65.4°]`（`params.yaml` 的 `limits.beta_min/beta_max`）比较：

| 实测结果 | 处理 |
|---|---|
| 实测 β 范围**包含**设计范围 | 照设计值走 |
| 实测范围**窄于**设计值 | 收窄 `limits`，否则软件会驱动到机械极限外 → 堵转 |
| 实测范围**宽于**设计值 | 可保持设计值，多出的行程是安全余量 |

**标定值与供电电压无关**（脉宽→角度由舵机内部电位器决定），
所以 5.0V 台架测得的标定可直接用于整机 6.0V。变的只是带载保持力。

## 1. 装配顺序

### 1.1 打印件检查

| 检查项 | 判据 |
|---|---|
| P5 大腿 ×4 | L1=100mm（髋端面到膝孔中心），膝孔 φ5 通 |
| P6 小腿 ×4 | L2=110mm（膝孔到脚垫孔），脚垫孔 M3 |
| P3 髋支架 ×4 | 舵机舱位贴合，引线出口朝内 |
| P4 髋轴承座 ×4 | 双耳孔位对齐，无变形 |
| P7 膝轴承座 ×4 | 法兰轴承压入无松动 |

打印件公差问题先处理掉：孔略紧可轻微扩孔，略松加垫片。**轴承孔必须紧配**——松动会产生 docs/gait_design.md §7.2 表中的柔性误差。

### 1.2 髋关节组装（每腿）

```
1. MG996R 装入 P3 支架，引线朝内走线槽
2. 输出轴装 P4 轴承座，双耳固定到机身角
3. 大腿 P5 用 M3 长螺钉 + 舵机盘（直驱）连接输出轴
4. 双耳固定螺丝加螺纹胶 —— 关键：单耳固定会让输出轴在负载下摆动
```

**要点**：舵机盘直驱，单盘长度须 ≥60mm 保证抗弯；若 100mm 大腿单盘不够，用双盘夹持。

### 1.3 膝关节组装（每腿）

```
1. P7 法兰轴承（MF105ZZ 级）压入膝孔
2. 膝输出舵机装于大腿末端，输出轴朝外
3. 小腿 P6 用 M3 螺钉连接膝输出盘
4. 膝轴惰侧：轴承 + 平垫 + 螺钉，用螺纹胶固定
```

**要点**：膝轴惰侧**必须用轴承**，不能只靠螺丝怼塑料孔。这是降低 flex 误差的关键（docs/hardware.md §6）。

### 1.4 脚垫

Φ15mm 中硬度橡胶，微凹面（凹面增加接地面积，降低压强与滑移）。用强力胶或螺纹胶固定于小腿末端 M3 孔。

### 1.5 电子层

```
下层板：4 个髋舵机、2S 电池仓（下层板中央低位）
上层板：ESP32、PCA9685、UBEC，预留 25×25mm 视觉板位
层间距 30mm，用 M3 铜柱连接
```

走线要求：

| 要求 | 说明 |
|---|---|
| 舵机电源粗线 | 16AWG 从 UBEC 6.0V 输出直接到 PCA9685 的 **V+**，不经开发板 |
| 信号线 | 22AWG，I2C 走 22cm 以内最佳；**无需串联电阻**（VCC=3.3V，模块 10kΩ 上拉已在 3.3V 轨） |
| 顶板凹槽 | 线缆嵌入，任何姿态不受挤压 |
| 仰面凸台 P10 | 翻倒时稳定支撑，不压线、不触舵机盘 |

### 1.6 接线（按 docs/hardware.md §5）

```
PCA9685 SDA → ESP32 GPIO21
PCA9685 SCL → ESP32 GPIO22
PCA9685 VCC → 5V
PCA9685 GND → GND（与舵机共地）
PCA9685 OE  → GND
通道 0..7 → FL.h FL.k FR.h FR.k RL.h RL.k RR.h RR.k
```

## 2. 首次上电检查

**机器人架空，脚不着地。**

| 序 | 检查 | 判据 |
|---|---|---|
| 1 | 仅插主控，不插舵机电源 | 串口无乱码，`ping` 有响应 |
| 2 | 插舵机电源（机器人仍架空） | 无异常发热，`cal scan` 八路依次小幅摆动 |
| 3 | 通道-腿序对应 | FL 对应左前腿，FR 右前，RL 左后，RR 右后 |
| 4 | 极性 | 每条腿髋摆动方向符合预期（不应有关节反折） |
| 5 | 齿轮与舵机盘 | 摆动全程无卡滞、无跳齿、无顶死端点 |

任一项不符立即断电排查，不要继续下一步。

## 3. 舵机标定（逐机）

MG996R 批次差异大，标定不可省。标定顺序：单路 → 逐腿 → 全机。

### 3.1 单路标定（CLI `cal enter` / Web `cal_enter`）

对每一路（ch 0..7）：

| 步 | 动作 | 记录 |
|---|---|---|
| 1 | 发小角度指令，观察是否在中位 | 定 `neutral`（机械中位脉宽） |
| 2 | 缓慢加正向，观察何时开始顶死 | 记正向可用端点，减 5~10µs 作 `max` |
| 3 | 同法负向 | 得 `min` |
| 4 | 若运动方向与指令相反 | 置 `reverse=true` |
| 5 | 装腿后目视调中位（大腿/小腿几何姿态） | 微调 `trim` |

**严禁贴死端点**：顶死时舵机持续堵转发热，几分钟即可损坏。

### 3.2 全机几何标定

标定八路后，机器人落地，执行 `pose stand`，测量并调整：

| 参数 | 测量方法 | 目标 |
|---|---|---|
| L1 实测 | 髋轴心到膝轴心 | 记录到 `geom`（模型 100mm） |
| L2 实测 | 膝轴心到足端接触点 | 记录到 `geom`（模型 110mm） |
| α 大腿倾角 | 大腿与水平面夹角 | 25~35°（模型 30°） |
| β_cruise | 站立时小腿与水平面夹角 | 36°~44°（模型 39.5°） |
| 站立高度 | 地面到下层板底面 | 115~125mm |
| 四角水平 | 机身是否水平 | 俯仰/横滚各 <2° |

俯仰偏 → 调前/后膝 `trim`。横滚偏 → 调左/右膝 `trim`。四角不平 → 调对应髋 `neutral` 至外八对称。

标定后执行 `cal save`（Web 为 `cal_save`），重启验证保持。

## 4. 几何标定（真实测量）

| 步骤 | 内容 |
|---|---|
| 1 | 用 `params show` 查看当前生效参数 |
| 2 | 机器人站立，量出站立高度 H 实测 |
| 3 | 反推 β_cruise：`sin(β) = (H - L1·sin(α)) / L2` |
| 4 | `params set geom.beta_cruise_deg <值>`，重启或 `pose stand` 生效 |
| 5 | 若整段高度调节范围偏移 → 调 L2 |
| 6 | 满意后 `save_params` 落 NVS |

真实测量值覆盖模型值后，步态的滑移残差会显著下降（docs/gait_design.md §7.2 的「标定残差」项）。

## 5. 首次行走

| 序 | 动作 | 观察 |
|---|---|---|
| 1 | `pose stand`，静置 30s | 舵机不过热；足端不滑；机身不晃 |
| 2 | `gait crawl` + `speed 20`，走 1 个周期 | 单腿顺序抬起放下，落点在原方位附近 |
| 3 | 走 20 周期 | 直线偏离 <50mm；无异响；脚垫不松 |
| 4 | `speed 50` | 速度线性提升，无丢步 |
| 5 | `gait trot` + `speed 30` | 对角腿同步；10 周期内保持直行 |
| 6 | `strafe 100` | 转向 → 直行 → 转回；总耗时约 5~7s |
| 7 | `nudge 30 30` | 棘轮微调；位移约 30mm；确认地面摩擦足够（橡胶垫过紧则搓不动） |
| 8 | `lean 5 5` | 机身横滚俯倾 5°，回中正常 |

出现以下情况立即 `estop` 并回到对应章节：

| 现象 | 排查 |
|---|---|
| 走几步后偏航 | 四腿外八角不对称；重新标定各腿 `neutral` |
| 支撑脚明显搓地 | β_cruise 太接近伸直位；重标 β |
| 腿间互相干涉 | α 不对；回 gait_sim 扫参 |
| 舵机持续嗡鸣发热 | 有顶死端点；检查 `min/max` 余量 |
| 机身越走越低 | 电池电压跌落；测舵机轨电压（低于 5.5V 即 UBEC 不够，硬件.md §4 校核表） |
| 走几步翻倒 | 重心过高或转向过快；降站立高度、限速 |

## 6. 参数调优

调参顺序（改一个测一个，记录）：

1. **站立高度**（`geom.beta_cruise_deg`）：太高不稳，太低跨障差。目标 120mm
2. **步幅**（`gait.stride_mm`）：先 45mm 试稳，再每次 +5mm
3. **周期**（`gait.period_s`）：1.5s 是下限，太快丢步
4. **抬脚高度**（`gait.lift_mm`）：25mm 起步，够跨线缆即可
5. **速度**（`speed`）：稳定前不超过 50%

**先在 gait_sim 里扫参，再上实机**（docs/gait_design.md §9 验收项）。实机调参是最后一步。
